# Стабильные идентификаторы и версии контрактов

> Статус: **Закрыто в v4** (ADR 0004): id обязателен — `contribute(id, spec)`, ключ и адрес `${pluginId}/${contributionId}`. Версионирование имени слота осталось соглашением.

## Проблема

Declarative contribution получает React key из идентификатора плагина и своей
позиции в массиве `contributes`. Вставка нового элемента в начало массива меняет
ключи следующих элементов и перемонтирует их вместе с локальным состоянием.

Имя slot одновременно служит адресом и не сообщает, совместимы ли две версии
его props. При независимом выпуске host и плагина несовместимое изменение
контракта обнаруживается слишком поздно.

## Предложение

Добавить обязательный стабильный `id` contribution:

```tsx
const Nav = defineSlot<NavProps>("acme/navigation/v1")

const pricing = definePlugin({
  id: "pricing",
  contributes: [
    Nav.contribute({
      id: "pricing-link",
      order: 20,
      component: PricingLink,
    }),
  ],
})
```

Полный идентификатор contribution строится как
`<plugin-id>/<contribution-id>`. Именно он используется как React key, в
диагностике, конфигурации и overrides.

Breaking-изменение props или поведения slot оформляется новым именем с major
version: `acme/navigation/v2`. Старую и новую версии можно держать одновременно
на время миграции.

## Миграция

В совместимом релизе `id` можно сделать необязательным и сохранить позиционный
fallback с development-предупреждением. В следующем major-релизе `id` становится
обязательным для declarative contributions. Runtime fills продолжают получать
внутреннюю идентичность при монтировании.

## Границы

- Библиотека не согласовывает версии автоматически.
- Наличие `/v1` в имени slot является соглашением, а не semver-движком.
- Один плагин не может объявить два contribution с одинаковым `id`.
- Изменение `id` считается намеренной потерей React identity.

## Критерии готовности

- Вставка и удаление соседнего contribution не перемонтирует остальные.
- Duplicate ID обнаруживается до рендера host.
- Идентификатор присутствует в ошибках и resolved graph.
- SSR и hydration используют одинаковые ключи.
- Документация описывает переход на новую major-версию slot без остановки
  старых потребителей.
